# 数据契约 v1

`pages/lp2_56.json` 与 `lp2_57.json` 从 pinned master 的末尾页段程序化提取。
目录文件名始终采用 LP2 原始 0..57 页码。iBotPeaches 的合并页码 73/74 对应 LP2 56/57，原图 SHA-256 完全相同。

每个 token 有稳定的 `page:source_offset` ID、原字符、类别、0-based 符文序号、
0..28 GP index、拉丁选项、素数值、行、段、列、图像路径及包含区域。所有非符文字符也保存。
`raw` 是原始转写的原样片段；`/` 是原图换行，文件中的换行只是转写排版。
`&` 是转写标记的段落，`$` 是章节段标记。页边界在提取坐标和 page 字段中保存。
`;` 未在 master 图例定义，故记录为未解决的分隔符歧义。标点含义不是本轮独立验证结论。

图像坐标按 2400×3600 原图，矩形格式 `[x0,y0,x1,y1]`；通常是人工估计的**整行包含区域**，
两枚放大首字有单独区域。它不是逐字形精确框，也不意味着已完成第二位人员的逐像素校对。
跨来源比较核对符文序列；iBot Markdown 丢掉了不少原标点，因此不能拿它证明标点的精确性。

Unicode ᛄ 是本版本 GP 的 J 表示；未知符文触发错误，不能自动替成形近字。
`C/K, S/Z, NG/ING, IA/IO` 是转写选项，不能混同于字形识别歧义。
严格展示保留 `EUERY`、`DIUINITY`；不自动改成 EVERY/DIVINITY。

`synthetic/training.txt` 与 `heldout.txt` 是本项目编写的合成基准语料，均在首次随机密钥生成前保存，
不是历史解密文本。训练仅读取前者；后者用于验证。
编码规则只用于合成基准：TH 合为一符文，V→U、K/Q→C、Z→S，其余字母单符文，去掉非字母。
因此该基准覆盖字母表的一个子集，不代表全部 Runeglish 拼写分布。
