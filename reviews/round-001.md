# 本轮复核与限制

复核者：当前实现代理；不是第二位独立研究者。独立验证指不同模块/信息通路，不能等同于独立人员复核。

## 已验证

- 两个仓库的 56/73 和 57/74 原图分别逐字节一致；两份转写的 85/95 个符文序列完全相同。
- GP 原图已目视查看，映射表的 29 行由测试与 pinned Markdown 表核对。
- 解码器只接收符文 token 和参数；没有访问公开明文。期待值模块只读上游 `Plaintext`（不读 `Cleaned up Plaintext`），
  根据独立的原密文每词符文数约束 Latin 分段，要求唯一解，再逐项比较完整符文序列。
  它没有调用解码器或利用候选输出选择分段。
- 56 页的 `202` 来自上游展平文本的字符位置，程序转换为 rune ordinal 56；不消费素数，故 85 个符文消费 84 个素数。
- 无跳位对照首个分歧在 ordinal 56，共 29 处不匹配；完整失败输出已保存。
- 验证端的负测试展示：错误明文和错误密钥仍可互相反向加密一致，因此 roundtrip 不是充分证据。
- 搜索 worker 使用 `-I -S`，安装 Python audit hook 后拒绝文件打开、目录枚举、网络和子进程。
  输入字段白名单拒绝 seed 字段；实际文件读取探针被拒绝。worker 没有导入验证模块。

## 不能据此断言

- 不证明两份社区转写的历史独立性，也没有第二位人员完成逐字形、逐分隔符校对。
- 图像定位多数只精确到整行区域；语义分段、红字/点阵/装饰仍需更细的标注。
- 上游 57 页 cleaned 文本省略/改变了一些符文对应的词尾；本轮严格输出保留 NG/ING、复数词尾和 DIUINITY。
- 三次随机密钥用同一篇未调参长文本，不是三个独立文本；评分差相同不能当成三份独立语言学证据。
- 合成题是无跳位素数流子族；密钥范围小、文本长、词频特征强。没有证明可恢复任意密钥、未知跳位或未解页。
- CPython audit hook 是对本项目受信代码的信息隔离措施，不是防恶意程序的操作系统安全沙箱。
- 没有根据语言模型补写任何解密词句；合成基准文本由项目编写，并明确不属于历史解密结果。
- 原图出处/PGP 身份、56 页散列目标、QuickStart 的统计及其他社区结论未独立验证。

## 开发期错误（不计为密码学阴性）

1. PowerShell Invoke-RestMethod 访问 GitHub API 出现 TLS authentication 错误；切换标准 Python urllib 成功，未关闭证书验证。
2. 首次控制台输出符文遇到 cp1252 UnicodeEncodeError；统一使用 `python -X utf8`。
3. Python 获取 QuickStart 返回 HTTP 403；来源清单明确使用原有 HTML 快照。首次获取命令退出 1，第二次带已标记回退成功。
4. 一次交互式正则探查被 PowerShell 对反引号的解释破坏，re.error，退出 1；改用保存的 Python 文件。
5. 上游本地 git status 遇到 Git/sh signal pipe 错误；没有更改上游 checkout，也没有依赖该命令证明工作树干净。

首次 `runs/dev-001-reproduce` 与早期完整闭环保留作开发证据；最终闭环额外包含离线 reproduction-bundle.zip，
因此今后即使代码继续变化，也能恢复本轮实际运行的代码和输入。
